# DashPi 开发说明文档

> 版本：2.1.1 ｜ 基于 Raspberry Pi 的开源智能显示项目

DashPi 是一个基于树莓派的开源智能显示项目，支持 LCD、Pimoroni Inky 电子墨水屏、Waveshare e-Paper 三类显示硬件，并通过 Web UI 进行配置与管理。它采用插件化架构，内置 24+ 个插件（天气、时钟、AI 图像、股票、ISS 追踪等），并支持按时段轮播（Loop）。

### 核心模块职责

| 模块 | 职责 |
|---|---|
| [src/dashpi.py](../src/dashpi.py) | Flask 应用入口，初始化 Config / DisplayManager / RefreshTask / WifiManager，注册蓝图，启动 Waitress 服务（生产端口 80，开发端口 8080） |
| [src/config.py](../src/config.py) | 设备配置读写，基于 `device.json`，使用 `_config_lock` 保证线程安全，采用临时文件 + rename 原子写入防止掉电损坏 |
| [src/model.py](../src/model.py) | `LoopManager` 管理多个按时段调度的 Loop；`Loop` 内含 `PluginReference` 序列；`RefreshInfo` 记录上次刷新元数据 |
| [src/refresh_task.py](../src/refresh_task.py) | 后台守护线程，按轮播间隔触发刷新，处理手动更新请求、循环切换、自动刷新、WiFi 重连与 AP 模式 |
| [src/display/display_manager.py](../src/display/display_manager.py) | 启动时按 Inky → LCD → mock 顺序自动检测硬件，统一处理图像处理流水线（方向 / 缩放 / 增强 / 过渡动画 / 亮度调度） |
| [src/plugins/plugin_registry.py](../src/plugins/plugin_registry.py) | 扫描 `plugins/` 目录，根据 `plugin-info.json` 动态 `importlib` 加载插件类并实例化 |

## 二、功能特性

### 显示支持

| 显示类型 | 硬件 | 特性 |
|---|---|---|
| **LCD** | Waveshare 7" HDMI IPS（1024×600） | 全彩、触控、背光亮度调度、快速刷新过渡动画 |
| **Inky e-ink** | Pimoroni Inky Impression（13.3/7.3/5.7/4"）、Inky wHAT 4.2" | 类纸观感、超低功耗，I2C 自动检测 |
| **Waveshare e-ink** | Spectra 6、黑白、双色多尺寸（不含 IT8951） | 多尺寸多色彩，SPI 通信 |

### 核心能力

- **硬件自动检测**：首次启动按 Inky I2C → LCD framebuffer → mock 顺序探测，结果写回 `device.json`
- **Web UI**：浏览器访问 `http://<hostname>.local` 或 IP，配置显示、管理插件、设置 Loop
- **24+ 内置插件**：Weather、Clock、AI Image、AI Text、NASA APOD、Art Museum、Stocks、ISS Tracker、Flight Tracker、ShazamPi、Calendar、Newspaper、Comics、RSS、Image Upload/Album/URL、Countdown、GitHub、To-Do List、Unsplash、Year Progress、Wikipedia POTD 等
- **Loop 调度**：按时段（如 09:00–18:00 工作时段、18:00–24:00 休闲时段）配置不同插件轮播；支持跨午夜、随机模式（带权重）、固定插件（Pin）
- **自动刷新**：单个插件可配置自动刷新间隔，无需等待 Loop 轮转
- **多设备**：同一网络可运行多个 DashPi，各自独立 hostname 与配置
- **WiFi 配网**：无 WiFi 时自动进入 AP 模式 + Captive Portal，扫码连接
- **自更新**：Web UI 设置页一键检查并应用更新（git pull + reinstall）
- **亮度调度**：按 day / evening / night 三时段自动调整背光，支持临时覆盖
- **PWA 支持**：含 manifest 与 service worker，可添加到主屏

## 三、架构设计

### 启动流程（[src/dashpi.py](../src/dashpi.py)）

```
解析参数 (--dev) 
  → 加载 logging.conf 
  → 创建 Config（读取 device.json / device_dev.json）
  → 创建 DisplayManager（自动检测硬件）
  → 创建 WifiManager
  → 创建 RefreshTask（注入 config / display / wifi）
  → load_plugins() 动态加载所有插件
  → 注册 6 个 Flask 蓝图
  → 设置安全响应头（CSP / X-Frame-Options 等）
  → refresh_task.start() 启动后台线程
  → 首次启动：生成启动画面；若无 WiFi 进入 AP 模式
  → waitress.serve(host=0.0.0.0, port=80/8080, threads=2)
```

### 刷新引擎（[src/refresh_task.py](../src/refresh_task.py)）

后台守护线程核心循环 `_run()`：

1. **计算睡眠时间**：取 Loop 轮播间隔（默认 300s）与插件自动刷新间隔的最小值；显示关闭时延长至 300s；首次启动延迟 3s
2. **等待**：通过 `threading.Condition.wait(timeout)` 等待，可被手动更新请求唤醒
3. **WiFi 检查**：3 次重试，失败则进入 AP 模式并跳过本轮
4. **决策刷新动作**（优先级）：
   - 手动更新请求
   - 固定插件切换（Pin 状态下显示插件不一致）
   - Loop 轮转到期 → `LoopRefresh`
   - 自动刷新到期 → `AutoRefresh`
   - 首次开机渲染
5. **执行**：实例化插件 → `generate_image()` 生成 PIL.Image → 经 DisplayManager 处理（方向/缩放/增强/过渡）→ 推送到硬件
6. **持久化**：每 12 次刷新批量写一次配置，减少 SD 卡磨损

### 配置存储（[src/config.py](../src/config.py)）

- 单文件 `device.json`，包含：`display_type` / `resolution` / `orientation` / `brightness_schedule` / `loop_config` / `refresh_info` / `plugin_order` / `plugin_last_settings_<id>` / `loop_override` 等
- API 密钥等敏感信息存于 `.env`（通过 `python-dotenv` 加载）
- 写入采用 `tempfile.NamedTemporaryFile` + `os.replace` 原子模式
- 线程安全：`_config_lock` 保护所有写操作

### 插件系统

**加载机制**（[plugin_registry.py](../src/plugins/plugin_registry.py)）：
- 启动时扫描 `plugins/` 下所有含 `plugin-info.json` 的子目录
- 通过 `importlib.import_module(f"plugins.{plugin_id}.{plugin_id}")` 动态导入
- 反射获取 `plugin-info.json` 中 `class` 字段指定的类，实例化后存入 `PLUGIN_CLASSES` 字典

**插件契约**（继承 [BasePlugin](../src/plugins/base_plugin/base_plugin.py)）：
- `generate_image(settings, device_config) -> PIL.Image`：必须实现，返回待显示图像
- `cleanup(settings)`：可选，插件实例删除时清理资源
- `generate_settings_template()`：可选，返回模板变量（含 `frame_styles` 边框样式）
- `get_loop_weight(settings)`：可选，返回随机轮播权重（如股市休市时降权）

**显示无关性**：插件应使用 `device_config.get_config("resolution")` 做相对尺寸布局，避免硬编码像素，确保在 800×480 e-ink 与 1024×600 LCD 上均正确渲染。

## 四、开发指南

### 4.1 开发环境（无需硬件）

`--dev` 标志支持在 macOS / Linux / Windows 上脱离树莓派与物理屏幕开发，使用 `MockDisplay` 将渲染结果输出到 `mock_display_output/latest.png`。

#### 方式一：传统 venv

```bash
git clone https://github.com/SHagler2/DashPi.git
cd DashPi

python3 -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate

pip install -r install/requirements-dev.txt
bash install/update_vendors.sh    # 更新前端 vendor 依赖
python src/dashpi.py --dev        # 启动开发服务器
```

访问 http://localhost:8080

#### 方式二：Devbox（推荐跨平台）

```bash
# 安装 devbox（可选 direnv）
command -v devbox >/dev/null || curl -fsSL https://get.jetify.com/devbox | bash

git clone https://github.com/SHagler2/DashPi.git
cd DashPi                        # 若启用 direnv 会自动进入 devbox shell

devbox run dev                   # 或 devbox shell 后 python src/dashpi.py --dev
```

Devbox 会自动安装 Python 依赖、chromium 浏览器等，配置见 [devbox.json](../devbox.json)。

### 4.2 浏览器依赖

DashPi 使用 Chrome 无头模式将 HTML 模板渲染为 PNG（部分插件依赖）。不同平台推荐：

| 平台 | 推荐包 |
|---|---|
| Raspbian / Debian | `chromium-headless-shell` |
| 其他 Linux | `chromium`（devbox 自动安装） |
| macOS | Google Chrome（默认路径 `/Applications/Google Chrome.app/...`） |
| Windows | Chromium 或 Google Chrome |

DashPi 优先在项目 PATH（devbox）中查找，再查系统 PATH。

### 4.3 开发配置

- 编辑 [src/config/device_dev.json](../src/config/device_dev.json) 调整开发模式下的分辨率、方向、设备名等
- 修改代码后重启服务即可生效（无热重载）
- 渲染结果查看 `mock_display_output/latest.png`
- 日志配置见 [src/config/logging.conf](../src/config/logging.conf)

### 4.4 调试技巧

1. 通过 Web UI 配置插件并点击 "Display" 按钮
2. 检查 `mock_display_output/latest.png` 验证渲染
3. 终端实时查看完整错误堆栈
4. 复制现有插件（如 `clock/`）作为新插件模板
5. 系统包依赖见 [install/debian-requirements.txt](../install/debian-requirements.txt)，devbox 方式可跳过

### 4.5 测试

```bash
# 运行测试套件
pytest

# 测试单个插件（使用 scripts/test_plugin.py）
python scripts/test_plugin.py
```

测试配置见 [pytest.ini](../pytest.ini)。

## 五、部署指南

### 5.1 硬件准备

- **主板**：Raspberry Pi 4 / 3 / Zero 2 W
- **存储**：≥8GB MicroSD 卡
- **显示**（任选其一）：
  - LCD：Waveshare 7" 1024×600 HDMI IPS（支持触控）
  - Inky：Pimoroni Inky Impression（13.3/7.3/5.7/4"）或 Inky wHAT 4.2"
  - Waveshare e-Paper：Spectra 6、黑白、双色（**不支持 IT8951**）

### 5.2 烧录系统

使用 [Raspberry Pi Imager](https://www.raspberrypi.com/software/)：
- 系统：**Raspberry Pi OS Lite (64-bit)**（Lite 版节省内存，Pi Zero 必选）
- 通用设置：hostname、用户名密码、WiFi、时区
- 服务：启用 SSH（密码认证）

详细图文步骤见 [docs/installation.md](installation.md)。

### 5.3 安装

#### 一键安装

```bash
curl -sSL https://raw.githubusercontent.com/SHagler2/DashPi/main/install/bootstrap.sh | sudo bash
```

#### 分步安装

```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/SHagler2/DashPi.git
cd DashPi
sudo bash install/install.sh
```

### 5.4 安装脚本做了什么（[install/install.sh](../install/install.sh)）

1. **权限检查**：必须 sudo 运行
2. **停止旧服务**：若已运行则先停止
3. **启用硬件接口**：`raspi-config` 启用 I2C（Inky 检测）与 SPI（e-Paper 通信），添加 `spi0-0cs` overlay
4. **安装系统依赖**：从 [debian-requirements.txt](../install/debian-requirements.txt) apt 安装（git、python3、chromium-headless-shell、libopenblas 等）
5. **Bookworm 特殊处理**：配置 zramswap（zstd，60%）
6. **earlyoom**：防止低内存设备 OOM 卡死
7. **Swap 扩容**：低内存设备（<1GB）扩至 2GB
8. **部署源码**：软链接 `src/` 到 `/usr/local/dashpi/src`
9. **安装 CLI**：`cli/` 复制到 `/usr/local/dashpi/cli/`
10. **创建 venv**：`/usr/local/dashpi/venv_dashpi`，低内存设备分批 pip 安装
11. **安装可执行文件**：`dashpi` → `/usr/local/bin/dashpi`
12. **初始配置**：复制 `config_base/device.json` 到 `src/config/`（已存在则保留）
13. **注册 systemd 服务**：写入 `/etc/systemd/system/dashpi.service`，资源限制 `CPUQuota=40%`、`MemoryMax=380M`
14. **配置静默启动**：内核 cmdline 加 `quiet splash`、屏蔽 GPU 彩虹屏、mask tty1 getty、安装 splash 动画服务
15. **持久化日志**：journald 改为 persistent，上限 50M
16. **更新前端 vendors**
17. **提示重启**

> **主机名规则**：若 hostname 为 `inkypi`（兼容旧 InkyPi），则服务名与路径用 `inkypi`，否则用 `dashpi`。

### 5.5 服务管理

```bash
sudo systemctl restart dashpi.service    # 重启
sudo systemctl status dashpi.service     # 状态
sudo journalctl -u dashpi.service -f     # 实时日志
sudo systemctl stop dashpi.service       # 停止
```

[install/dashpi](../install/dashpi) CLI 入口支持：

## 六、定制化

### 6.1 开发自定义插件

详细步骤见 [docs/building_plugins.md](building_plugins.md)，核心流程：

#### 步骤 1：创建插件目录

在 `src/plugins/` 下新建目录，目录名即插件 `id`（全小写无空格）：

```bash
mkdir src/plugins/my_plugin
```

#### 步骤 2：编写插件类

创建 `src/plugins/my_plugin/my_plugin.py`，继承 `BasePlugin`，实现 `generate_image`：

```python
from plugins.base_plugin.base_plugin import BasePlugin
from PIL import Image, ImageDraw

class MyPlugin(BasePlugin):
    def generate_image(self, settings, device_config):
        width, height = device_config.get_resolution()
        img = Image.new("RGB", (width, height), "#ffffff")
        draw = ImageDraw.Draw(img)
        text = settings.get("title", "Hello DashPi")
        draw.text((width // 2, height // 2), text, fill="#000000", anchor="mm")
        return img
```

**关键约定**：
- 使用 `device_config.get_config("resolution")` 做相对布局，不要硬编码像素
- 配置缺失或 API key 无效时 `raise RuntimeError("清晰错误信息")`，会在 Web UI 显示
- 需要缓存可读写 `settings` 字典（如 `settings["index"]`），下次刷新可读取
- 需要清理资源时覆盖 `cleanup(self, settings)`
- 需要动态调整轮播权重时覆盖 `get_loop_weight(settings)`（如股市休市降权）

#### 步骤 3：配置页（可选）

创建 `settings.html`，定义 HTML 表单，`name` 属性会成为 `generate_image` 中 `settings` 字典的键：

```html
<div class="setting">
    <label>Title</label>
    <input type="text" id="title" name="title">
</div>
```

预填充编辑模式：

```javascript
document.addEventListener('DOMContentLoaded', () => {
    if (loadPluginSettings) {
        document.getElementById('title').value = pluginSettings.title || '';
    }
});
```

如需注入模板变量或启用样式设置：

```python
def generate_settings_template(self):
    params = super().generate_settings_template()
    params['custom_var'] = self.get_custom_variable()
    params['style_settings'] = True   # 启用预定义样式选项
    return params
```

#### 步骤 4：图标

放置 `icon.png`（与现有插件风格一致）。

#### 步骤 5：注册清单

创建 `plugin-info.json`：

```json
{
    "display_name": "My Plugin",
    "id": "my_plugin",
    "class": "MyPlugin",
    "repository": ""
}
```

`repository` 字段：发布为第三方插件时填 GitHub 仓库 URL。

#### 步骤 6：测试

```bash
sudo systemctl restart dashpi.service
```

验证：
- 服务启动时正确加载（无 import 错误）
- Web UI "Plugins" 页显示图标与名称
- 不同分辨率与方向下渲染正确
- 设置页表单渲染、保存、编辑预填充均正常
- Loop 中即时更新与轮播正常

#### 插件目录结构

```
plugins/{plugin_id}/
    ├── {plugin_id}.py          # 主脚本（必须）
    ├── plugin-info.json        # 注册清单（必须）
    ├── icon.png                # 图标（必须）
    ├── settings.html           # 设置页（可选）
    ├── resources/              # 静态资源（图片、数据）
    └── ...                     # 其他辅助文件
```

### 6.2 添加显示驱动

如需支持新显示硬件，继承 [AbstractDisplay](../src/display/abstract_display.py) 并实现：

- `initialize_display()`：硬件初始化
- `display_image(image, image_settings)`：将 PIL.Image 推送到硬件
- 能力标志：`has_touch()` / `has_backlight()` / `supports_fast_refresh()` / `display_type_name()`

然后在 [display_manager.py](../src/display/display_manager.py) 的 `_detect_display_type()` 与 `DisplayManager.__init__` 中加入检测与实例化分支。

### 6.3 修改设备配置

直接编辑 `src/config/device.json`（生产）或 `src/config/device_dev.json`（开发），或通过 Web UI 设置页修改。常用项：

| 键 | 说明 |
|---|---|
| `display_type` | `auto` / `lcd` / `inky` / `epd*in*`（Waveshare） / `mock` |
| `resolution` | `[width, height]` |
| `orientation` | `horizontal` / `vertical` |
| `inverted_image` | 是否旋转 180° |
| `brightness_schedule` | `{enabled, day_start, evening_start, night_start, day_brightness, evening_brightness, night_brightness}` |
| `display_transitions` | `{enabled, steps, duration_ms}`（LCD 过渡动画） |
| `loop_config` | Loop 调度配置 |
| `loop_enabled` | 是否启用轮播 |
| `loop_override` | `{type: "plugin"|"loop", plugin_id|loop_name}` 固定显示 |
| `timezone` | 如 `US/Central`、`Asia/Shanghai` |

### 6.4 配置 API 密钥

通过 Web UI "API Keys" 页面管理，密钥写入 `.env` 文件，运行时通过 `device_config.load_env_key("KEY_NAME")` 读取。各插件所需密钥详见 [docs/api_keys.md](api_keys.md)。

### 6.5 发布第三方插件

1. 新建独立仓库，建议命名 `DashPi-{plugin_name}`，便于 GitHub 搜索发现
2. 仓库需包含：
   - 以 `plugin_id` 命名的插件文件夹（结构同上）
   - README：一句话描述、截图、依赖的 API（文档链接、是否需要 key、限额/费用、维护状态）
3. 用户通过 `dashpi-plugin` CLI 或 Web UI 安装
4. 模板参考 [DashPi-Plugin-Template](https://github.com/SHagler2/DashPi-Plugin-Template)
5. 发布到 [3rd Party Plugin List](https://github.com/SHagler2/DashPi/wiki/3rd-Party-Plugins) 与 [Show and Tell](https://github.com/SHagler2/DashPi/discussions/categories/show-and-tell)

详细规范见 [docs/building_plugins.md](building_plugins.md#publishing-a-third-party-plugin)。

### 6.6 Loop 调度定制

通过 Web UI "Loops" 页或直接修改 `device.json` 的 `loop_config`：

- 创建多个 Loop，各指定 `start_time` / `end_time`（支持跨午夜，如 `22:00`–`06:00`）
- 每个 Loop 内添加插件并设置各自刷新间隔
- 时间范围越小的 Loop 优先级越高（覆盖大时段）
- 启用 `randomize` 后可用 `weight` 控制选中概率
- 支持临时 Pin 单个插件或 Loop（`loop_override`）
